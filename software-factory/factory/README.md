# Software Factory

Markdown instructions + one JSON board + one read-only dashboard. No daemon.

```
feature → spec-writer → permission check → builder (worktree factory/<id>)
 → security · ux · ui · code · qa  (parallel, independent)
 → wait for ALL FIVE → CHANGES? resume the SAME builder (max 2 rounds/attempt)
 → approver (decision.md) → HUMAN APPROVAL → merge
```

The session running the skill is the **orchestrator**: it alone spawns agents and
writes `board.json`. Agents write only their own report. The builder also edits
source/tests, only in `.factory-worktrees/<id>`. Even `APPROVE` never merges; you
approve the exact reviewed commit. A failed review cannot be overridden by `approve`.
These rules are instructions, not an OS-level security boundary.

## Windows setup

```powershell
cd D:\software-factory\software-factory
git status                                   # repo root = this folder, remote origin = faiqfarooq/software-factory
git add -A; git commit -m "Add software factory"   # factory needs a commit on main to branch from
```

Python 3.12 is installed but not on PATH. Either add
`%LOCALAPPDATA%\Programs\Python\Python312` to PATH, or use the full path below.

## Run the dashboard

```powershell
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -m http.server 8000 --bind 127.0.0.1 --directory factory
```
Open <http://localhost:8000/dashboard.html>. (Opening the file directly will not work; it needs HTTP.)

## Run a feature

| Runtime | Start in repo root | Invocation |
|---|---|---|
| Claude Code | `claude` | `/factory next` · `/factory <feature>` · `/factory approve <id>` · `/factory rework <id> <note>` |
| Codex | `codex` (trust the project so `.codex/` loads) | `$factory next` · `$factory <feature>` · `$factory approve <id>` · `$factory rework <id> <note>` |

First feature: `/factory next` (takes the first sample in `backlog.md`).
Pick one runtime per job; do not run both orchestrators at once.

## Files

| Path | Purpose |
|---|---|
| `.claude/skills/factory/SKILL.md` | The full protocol (single source of truth) |
| `.claude/agents/*.md` | 8 Claude agents: spec-writer, builder, approver, security: Opus; ux, ui, code, qa: Sonnet |
| `.agents/skills/factory/` | Codex skill: follows the Claude protocol with Codex substitutions; implicit invocation off |
| `.codex/agents/*.toml` | Codex agents, generated by `factory/sync-codex-agents.py`; **no model set**, they inherit your Codex model |
| `factory/board.json` | Job state (orchestrator-only writer) |
| `factory/jobs/<id>/` | `request.md`, `spec.md`, `build.md`, `round-N/review-*.md`, `decision.md`, `feedback-N.md`, `approval.md` |
| `factory/backlog.md`, `repo-context.md` | Queue; discovered commands/conventions |

Report formats: reviews start `VERDICT: PASS|CHANGES` then `COMMIT: <sha>`;
`decision.md` starts `APPROVE|ESCALATE` then `COMMIT: <sha>`.

## Editing

Change the loop in the Claude SKILL.md. Change roles in `.claude/agents/`, then run
`python factory/sync-codex-agents.py` to refresh the Codex copies. Keep the reviewer
list in the skill and `dashboard.html` (`ROLES`) aligned.

## Codex caveats

Codex has no Opus/Sonnet; reviewers run on your configured model. Codex documents
delegation in natural language (spawn, steer, wait, close; `/agent` in the CLI), not
fixed tool names, so continuing the same builder relies on Codex keeping that
thread. If five parallel reviewers exceed your limit, raise
`agents.max_concurrent_threads_per_session` in `~/.codex/config.toml`.
